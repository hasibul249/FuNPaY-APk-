FuNPaY NID লেখা পড়া — সার্ভার OCR সেটআপ (Google Gemini API, ফ্রি)
================================================================
কেন: ফোনের ভেতরের Tesseract ধীর ও বাংলায় ভুল করে। Gemini সার্ভারে ২-৪ সেকেন্ডে বাংলা + ইংরেজি দুটোই নির্ভুল পড়ে।
ফ্রি: Google AI Studio র ফ্রি কী দিয়ে চলে, কার্ড/বিলিং লাগে না (ফ্রি সীমা প্রতি মিনিট/দিনে সীমিত; অ্যাপে প্রতি ইউজার দিনে ১২ ছবির সীমা আছে)।
সতর্কতা: NID এর ছবি Google এর সার্ভারে যায় (তৃতীয় পক্ষ)। ফ্রি স্তরে Google ডেটা উন্নয়নে ব্যবহার করতে পারে; চাইলে পরে পেইড স্তরে যান।

আপনাকে যা করতে হবে (ক্রমে)
1) aistudio.google.com > Get API key > Create API key (আপনার আগের Gemini key হলেও চলবে)।
2) Supabase > SQL Editor এ backend/update-v2.53.sql Run করুন (একবার; আগে করে থাকলে লাগবে না)।
3) Supabase > Edge Functions > nid-ocr > supabase/functions/nid-ocr/index.ts এর নতুন কোড পেস্ট > Deploy। "Verify JWT" ON রাখুন।
4) Edge Functions > Secrets এ যোগ করুন: GEMINI_API_KEY = (ধাপ ১ এর key)। চাইলে OCR_DAILY_LIMIT = 12, GEMINI_MODEL = gemini-2.5-flash (না দিলে এটাই)।
   পুরোনো GOOGLE_VISION_KEY আর লাগবে না।
5) কোড GitHub এ তুলুন, OTA আপডেট এলে পরীক্ষা করুন।

না করলে কী হয়: key না দিলে বা ফাংশন ফেল করলে অ্যাপ নিজে ফোনের Tesseract পথে ফিরে যায় (ধীর, কিন্তু কাজ করে)।
সমস্যা হলে: Supabase > Edge Functions > nid-ocr > Logs দেখুন (GEMINI 400/403 = key ভুল; 429 = ফ্রি সীমা শেষ; 404 = মডেলের নাম ভুল)।

ML Kit (ফোনের ভেতরে, ফ্রি, তাৎক্ষণিক) — v2.56b
----------------------------------------------
- NID-র ইংরেজি লেখা ও সংখ্যা (নাম, NID নম্বর, জন্মতারিখ) ফোনেই <১ সেকেন্ডে পড়ে; কার্ড ঠিক দিক কিনা তাও সাথে সাথে যাচাই হয়।
- বাংলা অংশ (পিতা, মাতা, ঠিকানা) Gemini একই সময়ে সার্ভারে পড়ে। দুটো একসাথে শুরু হয়, একটা অন্যটার জন্য থামে না।
- নাম/NID দুই ইঞ্জিন মিললে "নিশ্চিত" (লক); না মিললে Gemini-র মান বসে কিন্তু ঘর খোলা থাকে, ইউজার ঠিক করতে পারে।
- এটা নেটিভ কোড, তাই OTA আপডেটে আসবে না: GitHub Actions থেকে নতুন APK বিল্ড করে ইনস্টল করতে হবে (build.gradle ও MainActivity স্ক্রিপ্ট নিজে ঠিক করে)।
- নতুন APK না বসালে অ্যাপ আগের মতো শুধু Gemini দিয়ে চলে।
